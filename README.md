# 経営指標診断ツール

決算データ（または決算前企業向けの月次試算表データ）をもとに主要な経営指標を自動計算し、中小企業庁の統計データと比較して診断するWebアプリです。複数のクライアント企業のデータをアカウントごとに管理できます。

将来的なサービス化を見据え、フロントエンド（素のHTML/CSS/JS）＋バックエンドAPI（Node.js/Express）＋DB（SQLite）の構成にしています。

## 主な機能

- メール／パスワードでのアカウント登録・ログイン（会社データはユーザーごとに分離）
- クライアント企業の登録・業種選択・一覧管理
- 決算データ（年次）または月次試算表データ（決算前企業向け・自動で年換算）の入力
- CSVによる一括インポート
- 自己資本比率・売上高経常利益率・総資本回転率・簡易ROE・流動比率・売上高付加価値率・労働生産性の自動計算
- 銀行融資審査目線の指標（債務償還年数・借入金月商倍率）を任意項目として追加可能
- 中小企業庁の統計データ（業種別）との比較・良好/平均的/要注意の自動診断
- 診断結果を組み合わせた「総評」文の自動生成（ルールベース、無料・即時）
- 指標の推移グラフ、業種平均との比較グラフ
- 複数クライアント企業の指標を横断比較・ランキング表示
- レポートの印刷／PDF保存（ブラウザの印刷機能を利用）
- 経営体力スコア（各診断項目を得点化した0〜100点の総合スコア・5段階ラベル）
- 次回訪問時に聞くべき質問リストの自動生成（要注意・平均的だった指標から仮説ベースの質問を提示）
- アクションプラン・進捗トラッキング（診断結果に基づく改善タスクの登録・完了管理）
- 事業承継レディネスモード（社長年齢・後継者の状況（任意入力）と財務指標を組み合わせた簡易コメント）
- 自社クライアント内での相対順位表示（業種平均だけでなく、自分が担当する他のクライアントと比べた順位・パーセンタイル）

## セットアップ

Node.js 22.5 以降が必要です（`node:sqlite` を使用しているため）。`node -v` で確認してください。

```bash
npm install
npm start
```

`http://localhost:3000` を開くとアプリが使えます。初回起動時に `data/app.sqlite` が自動作成されます。

開発中はファイル変更を自動反映する `npm run dev` が便利です。

### テスト

計算ロジックのユニットテストがあります。

```bash
npm test
```

## 使い方

1. アカウントを作成してログイン
2. 「クライアント企業を追加」で会社名・業種を登録
3. 会社をクリックして詳細画面へ。決算データを1件ずつ入力するか、CSVで一括インポート
4. 決算前でまだ1年分のデータがない会社は、「月次試算表（決算前・年換算して簡易診断）」を選び、経過月数を入力すると自動で年換算して簡易診断できる
5. データが1件以上あれば、推移グラフ・総評・診断結果が自動表示される
6. 有利子負債を入力すると、銀行融資審査目線の指標（債務償還年数・借入金月商倍率）も診断に追加される
7. 会社一覧の「複数社を比較する」から、登録済みの全クライアントを指標横断で比較・並び替えできる
8. 会社詳細画面の「レポートを印刷 / PDFとして保存」から、総評・グラフ・診断結果をPDF化してクライアントに渡せる

## CSVフォーマット

1行目はヘッダー、1行=1期間分のデータ。金額の単位はすべて「円」。

| 列名 | 内容 |
|---|---|
| 年度 | 期間のラベル。例: 2024年3月期 |
| 経過月数 | 省略可。1〜11を入れると「決算前の月次試算表」として年換算される。空欄または12以上なら決算実績として扱う |
| 売上高 | 円 |
| 経常利益 | 円 |
| 総資産 | 円 |
| 純資産 | 円 |
| 流動資産 | 円 |
| 流動負債 | 円 |
| 従業員数 | 人 |
| 付加価値額 | 円（不明な場合は空欄可。労働生産性・付加価値率の診断のみスキップされる） |
| 有利子負債 | 円（任意。入力すると債務償還年数・借入金月商倍率が診断に追加される） |
| 減価償却費 | 円（任意。債務償還年数の計算に使用。未入力なら0として扱う） |

サンプル: `data/sample_annual.csv`（決算実績・3期分）、`data/sample_monthly.csv`（決算前・月次試算表）

## 算出している指標

| 指標 | 計算式 | 観点 | 良し悪しの向き |
|---|---|---|---|
| 自己資本比率 | 純資産 ÷ 総資産 × 100 | 安全性 | 高いほど良い |
| 売上高経常利益率 | 経常利益 ÷ 売上高 × 100 | 収益性 | 高いほど良い |
| 総資本回転率 | 売上高 ÷ 総資産 | 効率性 | 高いほど良い |
| 自己資本当期純利益率（簡易ROE） | 経常利益 ÷ 純資産 × 100 | 総合力（本来は当期純利益を使うが簡易的に経常利益で代用） | 高いほど良い |
| 流動比率 | 流動資産 ÷ 流動負債 × 100 | 短期安全性 | 高いほど良い |
| 売上高付加価値率 | 付加価値額 ÷ 売上高 × 100 | 生産性 | 高いほど良い |
| 労働生産性 | 付加価値額 ÷ 従業員数 | 生産性 | 高いほど良い |
| 債務償還年数（任意） | 有利子負債 ÷ (経常利益＋減価償却費) | 銀行融資審査目線 | 低いほど良い |
| 借入金月商倍率（任意） | 有利子負債 ÷ (売上高 ÷ 12) | 銀行融資審査目線 | 低いほど良い |

診断は「業種平均（または目安）の1.2倍以上＝良好」「0.8〜1.2倍＝平均的」「0.8倍未満＝要注意」を基本ルールとしています。債務償還年数・借入金月商倍率は「低いほど良い」逆指標のため、専用のしきい値判定（債務償還年数は10年以内=良好・15年超=要注意、借入金月商倍率は3ヶ月以内=良好・6ヶ月超=要注意）を使っています。

## 総評コメントの自動生成

診断結果（各指標の良好/平均的/要注意）と複数期間の推移を組み合わせて、自然な日本語の総評文を自動生成します（`server/lib/commentary.js`）。

現時点ではルールベース（テンプレート合成）で実装しており、外部APIには依存しません。無料・即時・オフラインで動作するため、運用コストやAPIキー管理の手間がありません。将来的にClaude APIなどの生成AIに差し替えたい場合は、`generateCommentary(items, series, industry)` の入出力インターフェースを変えずに `commentary.js` の中身だけ差し替えれば、呼び出し側（`indicators.js`）を変更せずに済むように設計しています。

## 複数社比較・ランキング

`GET /api/companies/compare` が、ログイン中ユーザーが持つ全クライアント企業の最新指標（自己資本比率・売上高経常利益率・総資本回転率・ROE・流動比率・労働生産性・良好/平均的/要注意の件数など）をまとめて返します。会社一覧画面の「複数社を比較する」から、任意の指標で並び替えて確認できます。データ未入力の会社は「データ未入力」として表示されます。

## 経営体力スコア

各診断項目の判定（良好=100点・平均的=60点・要注意=20点）を単純平均し、0〜100点の総合スコアと5段階ラベル（優良・良好・普通・要注意・危険水準）を算出します（`server/lib/score.js`）。銀行の格付けのように、詳細を見る前に一言で状態を伝えるための指標です。会社詳細画面のほか、複数社比較のランキングでも表示・並び替えに使えます。

## 次回訪問時に聞くべき質問リスト

要注意・平均的だった指標をもとに、次回の訪問・面談で経営者に確認すべき仮説ベースの質問を最大5件、自動生成します（`server/lib/questions.js`）。大きな懸念点がない場合は、成長投資や事業計画についてのポジティブな質問にフォールバックします。診断を「見て終わり」にせず、次のアクション（面談）につなげることを狙いとしています。

## アクションプラン・進捗トラッキング

診断結果を踏まえて、会社ごとに改善アクション（やること・関連指標・期限）を登録し、完了/未完了を管理できます（`server/routes/actions.js`）。会社詳細画面の一番下から追加・完了・削除ができます。

## 事業承継レディネスモード

会社登録時（または会社情報の更新フォーム）で社長年齢・後継者の状況（決定済み／検討中／未定）を任意入力すると、財務指標（自己資本比率・債務償還年数）と組み合わせた簡易的な事業承継コメントを表示します（`server/lib/succession.js`）。両方とも未入力の場合はカード自体を表示しません。あくまで簡易的な参考情報であり、実際の検討には税理士・弁護士・事業承継の専門家への相談が必要である旨を常に明記しています。

## 自社クライアント内での相対順位表示

業種平均という「外部の目安」に加えて、自分が担当している他のクライアント企業と比べた相対順位（パーセンタイル）を表示します（`server/lib/ranking.js`）。会社詳細画面では自分の担当先の中での順位、複数社比較画面では各社の位置づけを確認できます。比較対象となるデータが2社以上ある場合のみ表示されます。

## PDFレポート出力

「レポートを印刷 / PDFとして保存」ボタンは、ブラウザの印刷機能（`window.print()`）を使って総評・グラフ・診断結果だけを整形して表示し、印刷ダイアログから「PDFとして保存」を選べるようにしています。日本語フォントの扱いが面倒なサーバーサイドPDF生成ライブラリ（pdfkit等は追加のフォント埋め込みが必要）を使わず、ブラウザ標準の印刷機能で確実に日本語を綺麗に出力する方針にしています。

## 比較データの出典

- 全産業の加重平均値（自己資本比率・売上高経常利益率・総資本回転率・ROE・付加価値比率）：中小企業庁「令和４年中小企業実態基本調査速報（令和３年度決算実績）」の公表値
- 業種別の売上高経常利益率・労働生産性：同調査で公表された「産業大分類別の１企業当たり売上高・経常利益・従業者数・付加価値額」から本ツールが算出した参考値
- 業種別の総資本回転率・ROE・売上高付加価値率：中小企業庁「令和元年中小企業実態基本調査」に基づく公開資料（[社長の教科書「経営指標とは」](https://suzuki-tax.net/shacho-kyokasho/management-indicators)）の業種別平均値
- 業種別の自己資本比率：同資料の「財務レバレッジ」（総資本÷自己資本）から 100 ÷ 財務レバレッジ で逆算した推計値
- 業種別の流動比率：中小企業庁「中小企業実態基本調査 令和３年確報（令和２年度決算実績）」の公表値（[freee会計「流動比率は高いほうがいい？」](https://www.freee.co.jp/kb/kb-accounting/current-ratio/)経由で確認）。「全産業（合計）」は11業種の単純平均（参考値）
- 債務償還年数・借入金月商倍率の目安：銀行の融資審査で一般的に用いられるガイドライン（業種別の公的データではない）

年度の異なるデータを組み合わせているため、あくまで目安・参考値です。正確な業種水準を確認したい場合は [e-Stat 中小企業実態基本調査](https://www.e-stat.go.jp/stat-search/files?page=1&toukei=00553010&tstat=000001019842) の産業中分類別データを直接参照してください。詳細な数値は `server/lib/benchmarks.js` にまとめています。

## API概要

すべて `/api` 配下。認証はセッションCookie方式。

- `POST /api/auth/register` `{email, password}`
- `POST /api/auth/login` `{email, password}`
- `POST /api/auth/logout`
- `GET /api/auth/me`
- `GET /api/companies/industries` 対応業種一覧
- `GET /api/companies/compare` 全クライアント企業の最新指標を横断比較
- `GET/POST /api/companies` クライアント企業の一覧・作成（`owner_age`・`successor_status` は任意項目）
- `GET/PUT/DELETE /api/companies/:id`
- `GET/POST /api/companies/:id/records` 決算/試算表データの一覧・追加
- `POST /api/companies/:id/records/import` `{csv: "..."}` CSV一括取込
- `DELETE /api/companies/:id/records/:recordId`
- `GET /api/companies/:id/diagnosis` 指標推移・診断結果・総評・経営体力スコア・次回訪問質問・事業承継コメント・クライアント内順位
- `GET/POST /api/companies/:companyId/actions` アクションプランの一覧・追加
- `PUT/DELETE /api/companies/:companyId/actions/:actionId` アクションプランの更新（完了/未完了切替）・削除

## 本番デプロイについて

`Dockerfile` / `render.yaml` / `fly.toml` を用意していますが、実際のデプロイ（アカウント作成・接続・環境変数の設定など）はご自身で行ってください。

**重要な注意点**: このアプリはSQLite（ファイルベースのDB）を使っています。Render の無料プランなど「永続ディスク」が付かないホスティングでは、サービスが再起動・再デプロイされるたびに `data/app.sqlite` の中身（登録ユーザーやクライアント企業のデータ）が消えてしまいます。動作確認だけなら問題ありませんが、実際にクライアントのデータを預かって運用するなら、以下のいずれかが必須です。

- Render: プランを Starter 以上にして `render.yaml` 内の `disks` 設定を有効化する
- Railway: Volume を追加してマウントする
- Fly.io: `fly volumes create` で作成したボリュームを `fly.toml` の `[mounts]` でマウントする
- 将来的に複数インスタンスでスケールしたい場合は、SQLiteからPostgres等への移行を検討する
